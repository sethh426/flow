## Critical Firebase Deployment Rules

### Always Check Current Project First
```powershell
firebase projects:list  # See all projects
firebase use <project-id>  # Switch to correct one
```

### Deployment Paths by Project
| Project | Deploy From | Command |
|---------|-------------|---------|
| `flowearlyadopters` | `flow-early-adopters/` | `cd flow-early-adopters; firebase deploy --only hosting` |
| `affiliateflow-abzfy` | Root (via GitHub Actions) | Auto-deploys on push to main |
| `flowinvestorglance` | Root `firebase.json` | Managed separately |

### Common Mistakes to Avoid
1. **NEVER** run `firebase deploy` from project root when targeting `flowearlyadopters` - it will deploy `client/out` instead
2. **ALWAYS** `cd` into the correct subdirectory with its own `firebase.json`
3. **CHECK** which project is active with `firebase use` before deploying
4. **REMEMBER** Firebase reads the closest `firebase.json` in parent directories

## Debugging Auto-Scroll Issues

### Root Causes Identified
1. Material UI `Tabs` with `variant="scrollable"` or `centered` prop calls `scrollIntoView` on mount
2. Browser scroll restoration kicking in
3. TextField autofocus (even implicit)
4. React's `useLayoutEffect` firing before scroll prevention

### Proven Solution Pattern
```html
<body>
  <script>
    // Disable scrollIntoView immediately
    Element.prototype.scrollIntoView = function() {};
    
    // Hammer scroll position during load
    const keepAtTop = setInterval(() => {
      window.scrollTo(0, 0);
    }, 10);
    
    // Clear after React mounts
    window.addEventListener('load', () => {
      setTimeout(() => {
        clearInterval(keepAtTop);
        window.scrollTo(0, 0);
      }, 300);
    });
  </script>
  <div id="root"></div>
```

### What DIDN'T Work
- Conditional `scrollIntoView` overrides (React fires after load)
- `scroll-behavior: auto` CSS only
- `scrollRestoration = 'manual'` alone
- `overflow: hidden` (blocks rendering entirely)
- `autoFocus={false}` alone

## Responsive Design Checklist

When making a page "truly responsive":
1. **Typography**: Use `fontSize: { xs: "...", sm: "...", md: "..." }` on all major headings
2. **Buttons**: `width: { xs: "100%", sm: "auto" }` for CTAs
3. **Spacing**: `spacing={{ xs: 3, md: 4 }}` on Stacks
4. **Padding**: `p: { xs: 2, md: 3 }` on Papers/Containers
5. **Tabs**: Avoid `scrollable` variant (causes scroll issues), use `centered` with responsive flex direction
6. **Forms**: Stack direction `{ xs: "column", sm: "row" }`

## Git Workflow Best Practices

### Before Any Code Change
1. Verify current branch: `git status -sb`
2. Check which files would be affected
3. Read existing code to understand context

### After Changes
1. Stage specific files: `git add <file>`
2. Descriptive commit: `git commit -m "Action: specific change made"`
3. Push immediately: `git push origin main`
4. For multi-file changes, commit in logical groups

### Commit Message Patterns
- "Add [feature]" - new functionality
- "Fix [issue]" - bug fixes
- "Remove [thing]" - deletions
- "Refactor [area]" - restructuring
- "Update [component]" - modifications

## Common Request Patterns

### "Make it responsive"
**Means**: Check ALL typography, buttons, spacing, forms, containers for breakpoint adjustments

### "It's dragging me to the bottom"
**Means**: Auto-scroll issue - check for:
1. `scrollIntoView` calls (Material UI Tabs)
2. Autofocus inputs
3. Browser scroll restoration
4. Tab/accordion focusing

### "Delete [old site]"
**Means**: 
1. Find Firebase project: `firebase projects:list`
2. Switch: `firebase use <project-id>`
3. Disable hosting: `firebase hosting:disable`
4. OR delete via console: https://console.firebase.google.com/

### "Push the changes"
**Means**:
1. Stage files
2. Commit with clear message
3. Push to origin main
4. If Firebase deployment needed, do that first

## Performance Optimizations

### CDN React Apps
- Use production UMD builds for final deployment
- Minimize inline scripts
- Leverage browser caching for unpkg assets

### Firebase Hosting
- Set `cleanUrls: true` to remove .html extensions
- Use rewrites for SPA behavior
- Enable compression in hosting config

## Lessons from Recent Issues

1. **Check the actual deployed file location** - Don't assume file paths match URLs
2. **Verify Firebase project before deploying** - `firebase use` is your friend
3. **Test auto-scroll fixes incrementally** - Start simple, add complexity only if needed
4. **Read error messages carefully** - "Cannot find path" means wrong directory
5. **Hard refresh to verify changes** - Ctrl+Shift+R to bypass cache
6. **Don't over-engineer** - Simple solutions often work better than complex ones
7. **Confirm which file is actually being edited** - grep to find content before assuming location
8. **Never create summary docs unless asked** - User prefers clean repo

## Self-Correction Protocol

When you make a mistake:
1. **Acknowledge it immediately** - "You're right, I..."
2. **Fix it fast** - Don't explain, just correct
3. **Learn the pattern** - Add to this document
4. **Move forward** - No dwelling

When user says "it still does X":
1. **Don't repeat previous solutions** - They didn't work
2. **Check actual deployed content** - May differ from local
3. **Try fundamentally different approach** - Not just variations
4. **Ask for verification** - "Did that fix it?" after deploy

## Efficiency Rules

1. **Batch parallel operations** - Read multiple files at once
2. **Multi-replace when possible** - Use `multi_replace_string_in_file` for multiple edits

4. **Cache context mentally** - Don't re-read same file multiple times
5. **Commit frequently** - Small, logical commits
